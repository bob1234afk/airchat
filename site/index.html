Download

Every build is made from the sources in the repository by the scripts next to it. Two of the formats have a catch, and both catches are written out below rather than discovered later.

Windows — installer

324 KB, self-extracting, no admin rights. It unpacks to %LOCALAPPDATA%\AirChat, checks that Node.js is present, puts a shortcut on your Desktop and starts it.

Wants Node.js 18+. Need a real app window instead of a browser tab? The Electron build below is that.

AirChat-Setup-0.1.0.exe

Windows — Electron app

106 MB, a proper desktop window with its own icon and no browser chrome, because it carries a whole Chromium inside. Installs per user, no admin rights.

Too big to sit in a git repository, so it is attached to the release rather than committed.

AirChat-Setup-0.1.0-electron.exe

macOS

AirChat.app, zipped with its executable bit intact, plus a make-dmg.command that builds a real .dmg on any Mac.

Unsigned, so the first launch needs right-click → Open. No DMG is committed because Apple's disk-image format can only be written on macOS by hdiutil.

AirChat-0.1.0-mac.zip

iPhone / iPad — needs signing

AirChat-0.1.0-unsigned.ipa is the real packaging shape: correct Info.plist, real icons, the real interface, and a placeholder where the compiled program belongs.

It will not install as it stands. An installable IPA needs Apple's compiler and a signing identity, both of which require macOS. The file exists so the signing step has everything except those two things, and START-HERE.md inside it gives the exact commands.

AirChat-0.1.0-unsigned.ipa

How it works

One Node process on your machine serves the interface, keeps the message store on disk, and pushes updates to every open browser over a WebSocket. Outbound messages go to AirChat always, and additionally through whichever channel the thread is pointed at; inbound messages from those networks land in the same thread.

Adding a network means writing one file with a send(), a configured() and a describe(). Nothing else in the app changes. 

server/
  index.js      HTTP API, WebSocket hub, webhooks, invites
  ws.js         a WebSocket server with no dependencies
  store.js      all data, one JSON file, written atomically
  router.js     one send -> AirChat + the thread's mirror
  adapters/     mock, bluebubbles, twilio, telegram
ui/
  app.js        the whole interface, no build step
  crypto.js     end-to-end encryption, in the browser

What is and is not protected

A chat that stays inside AirChat is end-to-end encrypted with AES-GCM: the key is made in the browser and travels in the part of the invite link after the #, which browsers never send to a server. The server, the file on disk, and Cloudflare only ever hold cipher text.

Protected

  • The text of messages in AirChat-only chats.
  • The key: it never touches the server or the disk.
  • A message altered in transit, or replayed into another chat — refused.

Not protected

  • Anything sent by iMessage, SMS or Telegram. A phone network has to read what it carries.
  • Metadata: what chats exist, who wrote when, how long each locked message is.
  • A key you lose, or a device somebody else is inside.

Run it from source

The whole app is the working copy. Nothing is compiled to start it.

git clone https://github.com/bob1234afk/airchat
cd airchat
npm start          # opens http://localhost:4000
npm run doctor     # checks the whole install, including the encryption

npm run build:sfx  # Windows .exe installer
npm run build:mac  # macOS .app (zipped)
npm run build:ipa  # unsigned iOS payload, ready to sign

To reach a friend away from home, start it with Start AirChat + Public Link.bat or node tools/tunnel.js: a free Cloudflare Quick Tunnel, no account, no domain. The address changes every run and dies with the window, and AirChat says so rather than handing out a link that cannot resolve.

AirChat is not affiliated with Apple, Cloudflare, Twilio or Telegram. iMessage has no public API: blue bubbles require Apple hardware in the loop, which is a limit of Apple's, not of this project.
